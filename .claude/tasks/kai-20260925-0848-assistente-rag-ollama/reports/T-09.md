## Desvios do plano
- Ruling: o PDF é parseado numa `worker_thread` (`new Worker(script, { eval: true })`), que faz `require` do `pdf-parse` pelo caminho resolvido no processo pai. O motivo é que o pdfjs 5.4.296 (empacotado no pdf-parse 2.4.5) carrega o worker via `import()` dinâmico, e dentro da VM do jest isso falha com "A dynamic import callback was invoked without --experimental-vm-modules". Tentei antes pré-carregar `globalThis.pdfjsWorker` via `createRequire` e `process.getBuiltinModule`, mas o jest intercepta os dois ("Must use import to load ES Module"). Mudar a config do jest em `package.json` está fora do escopo (só o T-02 mexe nele). Efeito colateral positivo: o parse, que é CPU-bound, sai do event loop.
- Aditivo: exportei a constante `TEXT_EXTRACTOR_GATEWAY = 'ITextExtractorGateway'` e o tipo `SupportedDocumentExtension`. O token string segue o que diz a Interface.
- Os arquivos foram escritos por heredoc (o hook de formatação não rodou) e depois passei `npx eslint --fix` só nos três `.ts` da task, o que equivale ao hook.
